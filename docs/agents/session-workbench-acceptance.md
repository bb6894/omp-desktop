# Session Workbench v1 — 人工验收清单（Phase 8）

自动化门禁之外，以下步骤需要真人操作确认。按顺序执行；任何一步失败即记录
现象与稳定码，不猜测绕过。

## 前置

- Windows 11 x64；`artifacts/omp-windows-x64.exe` 哈希与 manifest 一致
- `npm ci` 后 `npm run dev` 启动 Tauri 窗口（renderer-next 在 Tauri 在场时自动走真实传输）

## A. 启动与会话列表

1. 冷启动窗口 → 左侧出现「进行中 / 等待你处理 / 已完成」三组；
   无会话时中央显示「选择或新建一个会话」。
2. 关闭重开 → 自动恢复上次项目/会话（localStorage 损坏时回落最新会话）。

## B. 新建任务（composer-first）

3. 「新建任务」→ 输入第一条指令 → 开始：
   - 出现专属子进程路由；首回合结束后列表出现新桌面会话并被选中；
   - 时间线流式渲染助手文本与紧凑工具卡（可展开有界输出）。
4. 运行中点「停止」→ 会话回到空闲且历史保留；再发消息可继续。

## C. 多会话隔离

5. 同项目连续创建两个任务 A/B：来回切换各 3 次，
   确认消息、工具事件、提问互不串扰（每会话独立子进程，T0.4 模型）。

## D. 内联提问与审批

6. 触发一个 select/confirm 类 `extension_ui_request`：
   时间线内联出现「等待你处理」控件；左栏该会话进入等待你处理分组。
7. 应答后条目标记已处理；Agent 继续执行。
8. （负例）切换到另一会话后再回来应答旧问题 → Host fail-closed，界面提示稳定码。

## E. 只读历史与 fork 继续

9. 左栏选一个「只读来源」行 → 中央无 composer，仅时间线 + 提示。
10. 点「继续（创建桌面副本）」→ 生成新桌面会话并选中；源 .jsonl 字节不变。

## F. 右侧上下文面板

11. 「变更」Tab → 有界文件列表（≤200，截断有标注）；点文件加载 vs HEAD 差异
    （二进制/未跟踪/超限各有专属文案）。
12. Output：以时间线内工具输出为准（v1 不做独立终端）。

## G. 键盘与视觉

13. Tab 顺序可达 rail/列表/composer 全部控件；focus-visible 描边可见；
    prefers-reduced-motion 下无闪烁动画。
14. 明暗两套主题下检查 1280×800 / 1440×900 / 1920×1080 三档截图
    （renderer-next/evidence/session-workbench-*.png 为自动基线）。

## H. 打包

15. `npm run verify` PASS:8 gates；`npm run build` 产出 MSI/NSIS 并安装启动冒烟
    （本清单随附构建日志为证）。

## 已知边界（非缺陷）

- 已完成分组在归档标记功能落地前恒为空。
- Output 面板 v1 复用时间线内的有界工具输出，不做交互式终端。
- fixture 模式（无 Tauri 环境）仅供离线演示，数据为冻结向量罐头。
